# 从零开始使用「探索 · 智能调参」

> 本教程带你从克隆仓库到跑完第一轮智能调参，全程以 Web 界面为主。
> 系统 = **Optuna TPE 贝叶斯搜索** + **LLM 监督 agent**：搜索器负责高效采样，
> agent 定期醒来阅读试验结果、诊断失败、调节搜索空间、守住护栏。
> 所有运行记录按**分区**管理、**永不删除**，随时可回看与对比。

## 1. 安装与启动

### 1.1 依赖

```bash
# Python 3.12+（推荐 3.14 已验证）
pip install -r requirements.txt
```

`requirements.txt` 含 optuna、PyYAML、anthropic、fastapi、uvicorn。
torch / torchvision 体积大且与环境强相关，请自行安装（只有内置 MNIST demo 需要，CPU 版即可）。

### 1.2 配置 LLM 端点（agent 需要）

在 `.env` 或系统环境变量里给出端点与凭据，settings 里用 `${ENV:变量名}` 引用，
**不把明文密钥写进配置文件**：

```bash
set ANTHROPIC_BASE_URL=https://你的端点      # 省略则用 SDK 默认
set ANTHROPIC_AUTH_TOKEN=你的凭据
```

验证连通性（两级探测：ping + tool-use）：

```bash
python cli.py check
```

> 没有 LLM 也能用：搜索时勾选/传 `--no-agent`，退化为纯 Optuna 巡航；
> 运行中 LLM 连续失败 3 次也会自动降级，不会卡死搜索。

### 1.3 启动 Web

```bash
python cli.py web
```

打开 **http://127.0.0.1:8000** —— 仓库随附前端构建产物（`web/dist`），
后端直接托管，单端口即用，**无需 Node**。

开发模式（要改前端源码时）：

```bash
dev.bat                 # 一键起后端 + Vite 前端（前端 http://127.0.0.1:5173）
# 或手工：python cli.py web 与 cd web && npm run dev 各开一个终端
```

## 2. 首次体验：内置 demo

首次启动会自动注册内置 demo 项目（MNIST 小网络，需已装 torch）并激活。
直接进「**运行与设置**」页点「开始搜索」即可看到完整流程：
试验逐条跑、曲线实时更新、agent 每 5 次试验醒来点评一轮。

> demo 数据会自动下载到 `mnist_data/`；`budget.data_fraction: 0.5`
> 表示抽样一半训练集加速，纯 CPU 几分钟就能看到结果。

## 3. 接入你自己的训练代码（从零）

这是本教程的重点：你有一个普通训练脚本，想让它接受智能调参。
以仓库自带的 `demo2/`（numpy 双月分类，argparse 传参、纯文本输出，
完全不认识调参协议）为参照示例。

### 3.1 两条接入路线

| 路线 | 适用 | 做法 |
|------|------|------|
| A. 原生契约 | 新写的脚本、愿意小改 | 脚本实现[三点契约](#7-训练脚本三点契约协议规范)，零适配层 |
| B. agent 适配 | 已有脚本、不想动它 | 保持原样，让**配置 agent** 阅读脚本并自动生成 wrapper（推荐） |

路线 B 全程如下。

### 3.2 新建项目

1. 页面右上角项目选择器 →「**新建 / 打开项目**」；
2. 目录浏览器里点选你的项目目录（含训练代码与数据的目录）；
3. 「主训练脚本」下拉里选入口 `.py`（供配置 agent 阅读；**忘选了也能事后补**，见 3.3）；
4. 点「创建 / 打开」。

系统会在你的目录里建立 `.tansuo/` 工作子目录（settings / search_space /
data / runs），**你的原文件保持原位**；相对路径一律相对项目目录解析。
目录已有 `.tansuo/settings.yaml` 时按「打开既有项目」处理，不重建模板。

### 3.3 训练脚本忘选 / 想更换

「**Agent**」页 →「**配置 agent（setup）**」子页：未登记脚本时面板会自动扫描
项目目录，按启发式评分（文件名提示、命令行收参、主入口、训练循环特征、
是否已实现协议）列出候选并给出中文依据，点选登记即可；也可以展开目录浏览手工挑。
登记时若 settings 仍是模板占位命令（`path/to/your_train.py`），会自动回填真实路径。

### 3.4 运行配置 agent

在同一子页点「**开始配置**」。agent 会：

1. 阅读训练脚本（CLI 参数、输出格式、指标含义）；
2. 起草 `.tansuo/settings.yaml`（指标与方向、驱动命令、预算、超时校准）
   与 `.tansuo/search_space.yaml`（按脚本暴露的超参数定域）；
3. 做 LLM 端点探针，随后跑**探针试验**验证链路；
4. 探针因协议不匹配失败时（普通脚本必然如此），按诊断自动生成
   **adapter wrapper**（把 JSON 配置翻译成命令行参数、把文本输出翻译回协议行），
   再探直到通过。

进度实时流在页面的「实时日志」与「会话事件」里。配置与搜索**硬互斥**，
同一项目内同时只能跑一个。

### 3.5 检查配置（可选）

「运行与设置」页可以直接编辑生效中的 settings/space；「搜索空间」页查看
参数定义与 agent 的历史补丁。确认主指标名与方向（`metrics.primary`）
和脚本实际打印的一致——这是最常见的人工修正点。

## 4. 启动一次搜索

「**运行与设置**」页「运行控制」卡片：

- **试验数**：本次新增多少次试验（系统自动换算成分区内总预算续跑）；
- **并发数**：留空取 settings 的 `budget.workers`；
- **时长上限**：到点不再派发新试验，在途试验跑完即以 `time_budget_exhausted` 优雅收尾；
- **备注**：写入分区 meta，便于日后辨认（如「换了新模型」）；
- 训练代码或优化目标变化时系统**自动新开分区**，也可手动「新开分区」。

页面实时显示预算预估（基于分区历史均值或 setup 探针），日志逐行滚动。
早停护栏默认开启：连续失败 ≥5 次自动早停，避免烧算力。

## 5. 读懂界面七个页签

| 页签 | 内容 |
|------|------|
| 仪表盘 | 主指标走势、top 试验学习曲线、最优配置、参数重要度、参数-取值关系 |
| 试验 | 每次试验的参数/指标/状态，点进去看**全量日志**；人工插队试验也在这里提交 |
| 搜索空间 | 当前空间定义 + agent 的空间补丁历史（每次 widen/narrow 都有审计） |
| Agent | 两个子页：**调参会话**（每轮唤醒的思考、工具调用、空间编辑）与 **配置 agent（setup）** |
| 提示词 | 系统/唤醒简报/配置三份提示词模板，可编辑、版本化、可回滚 |
| 对比 | 跨分区对比（仅优化目标相同的分区可比）：概览、最优配置、学习曲线叠加 |
| 运行与设置 | 启动/停止搜索、预算预估、成果交付（毕业赛 + 配置回写）、LLM 端点、Webhook |

## 6. 两份核心配置：settings.yaml 与 search_space.yaml

位于项目 `.tansuo/` 下，配置 agent 起草、人工可随时修正：

- `experiment`：实验名、`data_dir`（运行产物目录）、可选数据集身份与代码指纹附加路径；
- `metrics`：**唯一主指标**（驱动搜索方向）+ 若干观测指标；
- `adapter`：驱动方式。`mode: subprocess` 给启动命令，配置经环境变量传入；
  `timeout_s` 单次试验超时红线；`retry_on_fail` 瞬时故障自动重试；
- `budget`：总试验数、每多少次唤醒 agent、TPE 种子、数据抽样比例、并行数；
- `pruner`：`median`（中位数早停，默认）或 `hyperband`（epochs 跨度大时更省）；
- `agent`：模型名、端点（`${ENV:...}` 引用）、唤醒与工具调用限额；
- `storage`：记录库位置（sqlite，按分区自动分库）。

搜索空间每个参数必须带 `description`（配置即文档，也是 agent 的领域知识）；
支持 choice/float/int、log 尺度与 `depends_on` 条件参数。

## 7. 训练脚本三点契约（协议规范）

自己写脚本（路线 A）或审阅 agent 生成的 wrapper 时对照：

1. **读配置**：从环境变量 `TANSUO_TRIAL_CONFIG`（JSON 字符串）读本次试验的
   超参数；`config_via: file` 时改读 `TANSUO_CONFIG_FILE` 指向的临时文件；
2. **报告过程**：每完成一个评估步打印一行
   `##TANSUO## {"type":"epoch","epoch":N,"metrics":{...}}`
   （metrics 键名须与 settings 的指标名一致）；
3. **报告结果**：结束打印 `##TANSUO## {"type":"final","value":<float>}`
   并以退出码 0 结束。

非零退出 / 超时 / 缺 final 行 → 该试验记 FAILED（搜索继续，不中断）。
脚本的其它 print 输出视为噪音忽略，但会完整落盘到试验日志供排查。
参考实现：`demo/train_mnist.py`。

## 8. 记录分区与断点续跑

- 每次运行的记录落在 `<项目>/.tansuo/data/runs/NNNN-日期-时间/`，含分区库、
  meta、空间快照、报告与每次试验的全量日志；**永不删除**；
- **训练代码、数据集、优化目标**任一变化 → 自动新开分区，避免不可比的结果混跑；
- 重新「启动搜索」默认**续跑最新分区**（TPE 在已有试验上继续建模）；
  顶部「分区」选择器可回看任意历史分区；
- 「对比」页把目标相同的多个分区摆在一起看进步。

## 9. Agent 监督机制

- **唤醒节奏**：每 `budget.wake_every` 次试验醒来一轮（默认 5），阅读新试验、
  失败原因与护栏状态，可调用工具编辑搜索空间（widen/narrow，全程审计、可回滚）；
- **护栏**：连续失败早停、停滞早停、预算上限；唤醒简报里强制注入确定性规则，
  agent 的空间编辑不得越过 envelope；
- **失败感知**：试验失败的 stderr 摘要进唤醒简报，agent 会针对发散/超时/
  协议错误给出不同对策；
- **花费可见**：每轮 token 用量落审计，会话事件页可查累计；
- **提示词可定制**：「提示词」页编辑三份模板，版本化保存，新分区自动标记所用版本。

## 10. 进阶操作

- **人工插队试验**：「试验」页提交一组指定参数（可超定义域试错），原子排队、
  空闲即执行，来源与备注写入审计；
- **毕业赛**：「运行与设置 → 成果交付」，把最优配置在**全量数据 + 满轮数**
  下复验一次，产出 `reports/graduation.yaml`（verdict: pass/fail）；
- **配置回写**：同卡片内把 best 配置合并回你的配置文件（先备份、preview 再 apply）；
- **预算预估**：启动前按实测耗时估算 N 次试验总算力，可一键设为算力上限；
- **Webhook 通知**：会话结束 / agent 降级等事件推钉钉或自定义端点；
- **CLI 速查**：

| 命令 | 用途 |
|------|------|
| `python cli.py init` | 生成离线配置模板（无 LLM 的兜底） |
| `python cli.py setup --train X.py` | 配置 agent（Web「开始配置」的等价 CLI） |
| `python cli.py run --trials 30` | 跑搜索（`--workers`/`--hours`/`--gpus 0,1`/`--note`） |
| `python cli.py runs` / `runs show ID` | 列分区 / 看分区详情 |
| `python cli.py try '{"lr":0.03,...}'` | 人工试验入队 |
| `python cli.py graduate` | 毕业赛 |
| `python cli.py report` | 生成报告与 best.yaml |
| `python cli.py check` | 探测 LLM 端点 |

## 11. 常见问题

**点「开始搜索」报 400「训练脚本不存在」？**
项目还没配置：去「Agent → 配置 agent」登记训练脚本并跑一次配置，
或手工修正 `.tansuo/settings.yaml` 的 `adapter.command`。

**试验全部 FAILED、退出码 2？**
多半是启动命令找不到脚本或参数格式不对。点进任一失败试验看全量日志的
cmd 与 stderr——那里有完整现场。

**页面提示「数据库正被运行中的任务写入」（503）？**
搜索正在写分区库，只读视图短暂降级，稍等几秒刷新即可。

**试验总是超时？**
调大 `adapter.timeout_s`；若脚本支持按 epoch 折算，配置 agent 的超时校准
会按历史试验自动估算合理值。

**搜索中改了训练代码怎么办？**
下次启动自动新开分区（代码指纹变化），历史原样保留；想手动分界就
「新开分区」并写备注。

**记录会越攒越多吗？**
分区永不删除是设计目标（可追溯、可对比）；单分区一个 sqlite 文件，
体量随试验数线性增长，常规使用无需清理。
